# CI dependency images

Merge-group jobs start on separate hosted runners and each needs its own image pull. Their concurrent requests exhausted the public `mirror.gcr.io` Artifact Registry quota and ejected unrelated changes. The earlier move away from anonymous Docker Hub pulls addressed a different quota, but a shared public mirror was still an unowned dependency. CI therefore copies its declared Docker Hub images to separate Voucha GHCR dependency packages and consumes exact reviewed digests. The source registry remains the authoritative source of image bytes; GHCR is the controlled distribution point.

The [reviewed image inventory](../../../../ci/dependency-mirror/images.json) is the source of truth for upstream repositories, tracked release tags, and approved index digests. Renovate proposes upstream tag/digest changes in a PR; it never changes a consumed image by itself. The [mirror workflow](../../../../.github/workflows/dependency-mirror.yml) runs on main, stages complete multi-platform images locally, verifies their index digests, publishes into GHCR, and reads every platform manifest and blob back into a fresh OCI layout before advancing a tracked tag. An upstream tag moving without a reviewed inventory change produces a workflow warning. A source, copy, or verification failure fails the workflow and leaves the existing reviewed tag in place. The workflow does not delete dependency image versions: older approved digests can still be referenced by an in-flight CI run or historical revision. Renovate may propose new reviewed digests whenever its hosted run executes; that service's cadence is separate from the daily mirror workflow.

## Bootstrap and recovery

The producer workflow must be merged before any consumer points at its GHCR packages. Run its manual dispatch on main and check that every inventory entry has a successful exact-digest verification in the job summary. Newly published GHCR packages default to private. A package administrator must change each dependency package's visibility to **Public** in GitHub package settings; public visibility cannot be undone. Verify an unauthenticated exact-digest pull for the relevant runner architectures before merging the consumer change. Service containers start before checkout and cannot use a repository token to pull a private package; forked PRs also need anonymous access.

For a failed scheduled run, inspect its failed stage and keep the existing consumed digest. If an approved digest is unavailable at the source, restore its availability or review a new digest in a PR, then rerun the producer workflow. If a GHCR approved tag points to different bytes, stop and investigate; the copier refuses to overwrite that immutable tag. A successful manual dispatch after repair restores a missing copy without deleting older versions.

This mirror has storage and transfer cost. The cost has not been measured; operators should measure it before setting a deletion policy. Do not add a quota retry rule as a substitute for the owned source.
