# Vitest Mock Typing

[Back to Tests and Checks](tests.md#vitest-mock-typing)

Typed mock factories are enforced by `vitest/require-mock-type-parameters`, `vitest/prefer-import-in-mock`, and `jest/no-untyped-mock-factory`. Use `vi.mock<typeof import(...)>(import(...), ...)` in backend, lambdas, cloudflare-worker, and CI, and `vi.mock(import('specifier'), ...)` in web. Do not add file-level suppressions for these rules.

- **Loose mocks.** `VitestLooseMock` (declared per workspace) loosens only the mock function signature. Values passed to `mockResolvedValue()` or `mockReturnValue()` must still satisfy the real response type; build them with a typed fixture factory. A deliberately partial web factory keeps its runtime shape and uses a whole-module `as unknown as typeof import(...)` assertion.
- **Runtime-validation boundaries.** Cast only the invalid argument to its production parameter type via `Parameters<typeof fn>`. Do not widen the production signature or add a shared unchecked-input helper for test-only values.
- **Non-web tests do not mock internal modules.** Mock environment with `vi.stubEnv()`, mock external packages directly, and put provider seams under `@modules/<provider>` tagged `/* no-mistakes: integration=<provider> */` on the function that directly calls the provider. Prefer real PostgreSQL, Valkey, queue, and service integration tests over mocking internals: partial internal mocks and mock-only helper barrels drift when imports change and hide missing exports.
- **High-risk change.** Adding an export to a module that `.mock.test.*` files mock: the factory silently omits it unless it spreads `...(await vi.importActual(...))`. Search for those files when changing a module's exports.
- **Naming.** Files that call module-mocking APIs use the `.mock.test.*` suffix, and a `.mock.test.*` file without such calls fails too (`no-mistakes/vitest-mock-test-file-naming`).
- **Wrapper tests.** `web/lib/api/**` wrappers that translate option names into query params need a direct wrapper assertion for the wire key (`expectApiWrapperCall()`); page-level mocks do not replace it. API response bodies come from `web/test-helpers/api-responses/` factories, which default only on `undefined` so explicit `null` is preserved.
- **`next/navigation`.** Next hooks read React context and never `window.location`; the real `useSearchParams()` returns `null` in jsdom without a provider. Use the shared `navMockModule` and `createNavMock` singleton instead of hand-rolled per-test mocks, which silently diverge from the runtime contract. Components that read `window.location` inside an event handler use `window.history.pushState` and no hook mock.
- **Direct Server Component tests.** Invoking an async Server Component creates no request store, so shared helpers calling `headers()`, `cookies()`, or `draftMode()` throw. Prefer guarding the call in the shared helper with a valid no-request fallback (`getResolvedUiLocale()`); mock `next/headers` only when request data is the behavior under test.
- **Lazy children and icons.** Web setup seeds the English catalog and rejects unseeded localization requests. Mock a lazy child explicitly; doubles that invoke a `next/dynamic` loader register with `trackDynamicImport()` so the import cannot outlive jsdom teardown. Partial `lucide-react` mocks use `mockLucideReact`.
- Repository-wide suppression scans include hidden directories such as `web/.storybook`.
