# Coverage matrix

[Back to Dependency Updates](dependency-updates.md#coverage-matrix)

| Source                                                                              | Tool       | How it works                                                                                                                                                                                                                                                                              |
| ----------------------------------------------------------------------------------- | ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `package.json` deps + `pnpm-lock.yaml` (root and all `pnpm-workspace.yaml` members) | Dependabot | `npm` ecosystem, single root entry; Dependabot walks `pnpm-workspace.yaml` to discover all workspace members and updates `pnpm-lock.yaml` from the root. See note below.                                                                                                                  |
| Base images in `web/Dockerfile`, `backend/Dockerfile`                               | Dependabot | `docker` ecosystem.                                                                                                                                                                                                                                                                       |
| `actions/*`, `pnpm/action-setup`, etc.                                              | Dependabot | `github-actions` ecosystem. First-party release trains (`vouchington/vouchington-tooling`, `jonathanong/auto-harness`) are grouped per source repo and exempt from cooldown.                                                                                                              |
| `.nvmrc` (Node major)                                                               | Renovate   | Built-in `nvm` manager.                                                                                                                                                                                                                                                                   |
| `LYCHEE_VERSION` env var in workflow YAML                                           | Renovate   | Same regex annotation pattern. Annotation lives one line above the version literal.                                                                                                                                                                                                       |
| `ripgrep`, `shellcheck`, `selene`, `actionlint`, `zizmor`, `scc` in `.mise.toml`    | Renovate   | Regex `customManagers` block; inline `# renovate: datasource=github-releases depName=…` comments above each tool pin the correct release source.                                                                                                                                          |
| `nvm-sh/nvm/v…/install.sh` URL printed by `dev/initialize`                          | Renovate   | Regex customManager scoped to `dev/initialize`; annotation precedes the `echo` line.                                                                                                                                                                                                      |
| pnpm major in `pnpm/action-setup` `version` and Dockerfile `PNPM_VERSION`           | **Manual** | pnpm is not pinned; each site names one major. `pnpm/action-setup` (`latest-<major>`) self-updates to the newest release at least a day old, and Docker installs the newest. Bump every site together for a new major; `.github/workflows/pnpm-activation.test.mts` fails if they differ. |
| `ALPINE_SECURITY_REFRESH` ARG in `web/Dockerfile`                                   | **Manual** | Bump this cache key when responding to an Alpine security advisory so the shared `apk upgrade` layer reruns against the current package repository.                                                                                                                                       |
| `valkey/valkey-bundle` in workflows, `dev/initialize`, and mirrored tests           | Renovate   | One Docker regex customManager updates the exact image tag across CI, local initialization, and test fixtures in a single dependency PR.                                                                                                                                                  |

The root, backend, and Cloudflare Worker `package.json` manifests publish a Node `>=24.16.0`
compatibility floor. This is distinct from the repository's Node 26 development, CI, and deployed
runtime pins: `.nvmrc`, workflow setup, and Docker base images remain the Node 26 sources of truth.
