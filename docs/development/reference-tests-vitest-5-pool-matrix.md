# Vitest 5 Pool and Isolate Matrix

[Back to Pools, Isolation, and Vitest 5](reference-tests-vitest-projects.md#pools-isolation-and-vitest-5)

| Configuration                | Environment created                        | Isolation                                                     | Where                                                                                  | Why not the other option                                                                                                                                                                                                                                                                         |
| ---------------------------- | ------------------------------------------ | ------------------------------------------------------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `forks` + `isolate: false`   | once per worker                            | files in a fork share the module graph and process singletons | backend data/modules/aws/openai, `web-api`, `web-integration`                          | `threads` would put `valkey-glide` NAPI and PSQL pools in `worker_threads`; vm pools add cross-realm `instanceof` and leak memory. Fork-only diagnostics: [`reference-vitest-worker-exit-diagnostics.md`](reference-vitest-worker-exit-diagnostics.md)                                           |
| `forks` + `isolate: true`    | once per file                              | fresh process per file                                        | mocks, analytics, postgres-schema, `backend-real-glide-mq`, `i18n-extract-codemod`     | fresh module registry / `process.env` / real vs shim `glide-mq`; `i18n-extract-codemod` also needs a killable process because no-mistakes `analyzeProject` / `invocation.lock` cannot be SIGKILLed on the tooling threads pool ([#11686](https://github.com/jonathanong/filaments/issues/11686)) |
| `threads` + `isolate: true`  | once per file                              | fresh worker and environment per file                         | `web` jsdom, `web-storybook`, tooling (except `i18n-extract-codemod`), mock lambdas/CF | jsdom `window` and tooling `process.env` replacement; a file-level `vi.mock` must not leak. RTL `cleanup()` is not a module-registry reset                                                                                                                                                       |
| `threads` + `isolate: false` | once per worker                            | shared module graph                                           | non-mock lambdas / `cloudflare-worker`                                                 | no NAPI singletons; tests tolerate shared state                                                                                                                                                                                                                                                  |
| `vmThreads` / `vmForks`      | once per worker, fresh VM context per file | VM-realm isolation                                            | **unused**                                                                             | ESM-in-VM instability, `vmMemoryLimit` recycle cost, NAPI, and fork-only `execArgv` / `[vitest-fork-exit]` diagnostics                                                                                                                                                                           |
