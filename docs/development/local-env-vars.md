# Local Environment Variables

This is the source of truth for environment variables a developer may need for local setup. The
goal is that `./dev/initialize web` can start the full app with no developer-supplied env vars.
Cloud-backed features stay opt-in and should fail with clear setup guidance only when used.

For env-var and Dynamic Config migrations, run `./dev/config-inventory` first. It generates the
cross-surface checklist used to review local setup, deployment, docs, package gates, and runtime
config candidates. Shared local setup and deployment expectations come from the typed
[env-var contract](../overview/infrastructure/env-var-contract.md).

The generated local-setup rows in this page are drift-checked against `@ts-shared/env-contract`.
Everything else in the page stays hand-maintained unless a section note says otherwise.

## Turnstile

Normal local dev does not need Turnstile env vars. The web and backend default to Cloudflare's
public always-pass Turnstile test keys. Set `NEXT_PUBLIC_CLOUDFLARE_TURNSTILE_SITE_KEY` and
`CLOUDFLARE_TURNSTILE_SECRET_KEY` only for deployed staging/production or explicit local testing
with real Turnstile credentials. Native clients read the same
`NEXT_PUBLIC_CLOUDFLARE_TURNSTILE_SITE_KEY` site key unless `VOUCHA_TURNSTILE_SITE_KEY` is set. The
site key is browser-visible runtime public config; do not add new Docker build-time plumbing for it.

## Dynamic Config

Move only non-secret runtime behavior knobs to Dynamic Config. Credentials, ports, deployment
origins, runtime public browser config, and CI/test controls stay env-backed.

Good future candidates:

- Analytics behavior knobs (`ANALYTICS_BACKEND`) — blocked by a circular workspace dependency
  (`@data-stores/valkey` already depends on `@data-stores/analytics`); deferred.

Already Dynamic Config-backed: reCAPTCHA controls, feature flags, vote weights, post content
limits, rate limits, bloom filters, RSS feed discoverability, AI-generated content moderation
threshold (`moderation-config`), and Bedrock embeddings batch tuning
(`bedrock-embeddings-batch-config`).
