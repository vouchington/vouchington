# Local Web Validation Recovery

[Back to Tests and Checks](tests.md#local-web-validation-recovery)

Use this table before debugging a local web validation failure as an application bug. These
recoveries target known setup and host-environment failure modes. For CI (not local)
infrastructure-failure signatures such as Docker socket errors, runner loss, and Storybook
timeouts, see
[Classifying Transient Infrastructure Failures](ci.md#classifying-transient-infrastructure-failures).

| Symptom                                                                                                                                              | Likely cause                                                                                                                                                      | Next command                                                                                                                                                                                                                                                                        |
| ---------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Chromium reports `bootstrap_check_in`, Mach permission, or sandbox errors                                                                            | macOS process permissions or the agent sandbox blocked browser startup                                                                                            | Rerun the exact Playwright command outside the sandbox before changing app code.                                                                                                                                                                                                    |
| Local setup or validation command fails with `bwrap` sandbox setup errors                                                                            | The agent sandbox could not initialize for that command, but the command may work against host services                                                           | Rerun the exact setup or validation command outside the sandbox; for file-edit fallbacks, use the [agent-workflow skill](../../.agents/skills/agent-workflow/SKILL.md) rule instead. On a CI runner, the identical error is a host-provisioning failure, not a local sandbox quirk. |
| Playwright cannot start `node server.js`, or `web/.next/standalone/web/server.js` is missing                                                         | `./dev/initialize web` cleared `web/.next`, or the standalone build was never produced                                                                            | Run `node ci/setup-web-integration.mts` to rebuild the Next.js standalone server, copy standalone assets, and build the Worker bundle.                                                                                                                                              |
| `ERR_PNPM_VERIFY_DEPS_BEFORE_RUN` appears after a rebase or branch switch                                                                            | `node_modules` is out of sync with `pnpm-lock.yaml` or workspace package manifests                                                                                | Run `pnpm install`, then `pnpm run syncpack:lint && pnpm run no-mistakes` if package manifests or lockfiles changed. `.husky/post-checkout` auto-installs on branch switches that change manifests.                                                                                 |
| `.env`, `DATABASE_URL`, PostgreSQL, Valkey, or the worktree database is missing                                                                      | The worktree was not web-initialized, local services were stopped, or saved local state drifted                                                                   | Run `./dev/initialize web`, then `source .env`; use `./dev/reset` only if the schema or test data is still stale afterward.                                                                                                                                                         |
| DB-backed tests report stale PostgreSQL schema, missing columns, or blocked view recreation                                                          | A non-main worktree DB recorded an edited-in-place pre-launch migration before the latest schema shape                                                            | Run `./dev/initialize web` first; if the schema is still stale, run `./dev/reset`, then `source .env` and rerun the failing DB-backed check.                                                                                                                                        |
| Browser checks fail because Valkey stopped or cannot be reached                                                                                      | The worktree's Valkey container is stopped or stale                                                                                                               | Run `./dev/initialize web`, then confirm service state with `./dev/status`.                                                                                                                                                                                                         |
| A local Playwright spec fails, but the same command passes immediately after                                                                         | Local service state drifted during the first run, not during the isolated reproduce                                                                               | After the exact reproduce command passes, run `./dev/stop-services && ./dev/initialize web`, then `source .env` and rerun the spec.                                                                                                                                                 |
| Wrangler exits, logs `EMFILE`, or browser checks fail under descriptor pressure                                                                      | Playwright, Chromium, workerd, Next.js, backend, lambdas, PostgreSQL, and Valkey are competing locally                                                            | Inspect `cloudflare-worker/.wrangler/runtime/` logs and retry with `PLAYWRIGHT_MAX_WORKERS=1`; do not clear `.next` after a needed standalone build.                                                                                                                                |
| `createdb` or `psql` fails with "no such file" or "connection refused"                                                                               | The local PostgreSQL service is stopped, or the configured database target is unreachable                                                                         | Confirm that the host PostgreSQL 18 service is running (`brew services info postgresql@18` on macOS). Inspect `DATABASE_URL` in `.env`, correct its host or port if needed, then retry with `source .env && ./dev/initialize web`; do not replace a custom target with `PGHOST`.    |
| A manually QA'd prod build (`pnpm --dir web run build`) logs `[HMR] connected` in the browser console, or renders inconsistently across hard reloads | A stale service worker registered during earlier `next dev` browsing on the same origin is still active and serving cached dev-mode assets across server restarts | In the tab's console: `(await navigator.serviceWorker.getRegistrations()).forEach(r => r.unregister())`, then `(await caches.keys()).forEach(k => caches.delete(k))`, then hard reload again                                                                                        |

Initialization performs a non-destructive host-storage preflight before write-heavy setup. Initialization first uses a Bash-compatible required filesystem gate before nvm can install Node; its comprehensive probe discovers pnpm and Docker only after required probes pass. If either reports less than 5 GiB free, run the printed shell-quoted `df -h` command and review pnpm or Docker usage before removing anything. Optional pnpm store or Docker-root discovery failures warn; required worktree, home, or temporary-directory probe failures block.
