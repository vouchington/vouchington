# Local Web Validation Recovery

[Back to Tests and Checks](tests.md#local-web-validation-recovery)

Use this before debugging a local web validation failure as an application bug. A reset follows [Ephemeral worktree databases](../../AGENTS.md). For CI infrastructure-failure signatures, see [Classifying Transient Infrastructure Failures](ci.md#classifying-transient-infrastructure-failures).

| Symptom                                                                                                         | Likely cause                                                                                        | Next step                                                                                                                                           |
| --------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| Chromium reports `bootstrap_check_in`, Mach permission, or sandbox errors; setup fails with `bwrap` errors      | The agent sandbox blocked browser startup or could not initialize                                   | Rerun the exact command outside the sandbox before changing app code. On a CI runner the same `bwrap` error is a host-provisioning failure.         |
| Playwright cannot start `node server.js`, or `web/.next/standalone/web/server.js` is missing                    | `./dev/initialize web` cleared `web/.next`, or the standalone build never ran                       | `node ci/setup-web-integration.mts`                                                                                                                 |
| `ERR_PNPM_VERIFY_DEPS_BEFORE_RUN` after a rebase or branch switch                                               | `node_modules` is out of sync with the lockfile or manifests                                        | `pnpm install` (no flags; never `--frozen-lockfile` after a rebase)                                                                                 |
| `.env`, `DATABASE_URL`, PostgreSQL, or Valkey missing; stale schema; browser checks fail because Valkey stopped | Worktree not web-initialized, services stopped, or saved state drifted                              | `./dev/initialize web`, `source .env`, check `./dev/status`; `./dev/reset` only if still stale                                                      |
| A Playwright spec fails, then passes immediately on rerun                                                       | Local service state drifted during the first run                                                    | After the isolated reproduce passes, `./dev/stop-services && ./dev/initialize web`, then rerun                                                      |
| Wrangler exits or logs `EMFILE` under descriptor pressure                                                       | Playwright, Chromium, workerd, Next.js, backend, lambdas, PostgreSQL, and Valkey compete locally    | Inspect `cloudflare-worker/.wrangler/runtime/` logs and retry with `PLAYWRIGHT_MAX_WORKERS=1`; do not clear `.next` after a needed standalone build |
| A manually QA'd prod build logs `[HMR] connected` or renders inconsistently across reloads                      | A stale service worker from earlier `next dev` browsing on the same origin serves cached dev assets | Unregister service workers and delete caches in the tab console, then hard reload                                                                   |
