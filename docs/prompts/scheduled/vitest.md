Review Vitest tests. Pick at most one concrete, bounded improvement that is safe to ship in one PR.

Load `test-authoring`, `testing-rules`, and `vouchington-backend-tests`.

- Run the relevant test more than once when investigating reliability. For PostgreSQL or Valkey state, run it freshly cleaned (after `pnpm run db:clean`, run `pnpm run db:migrate` first) and again without cleaning. For aggregate, unscoped-list, or cleanup-count tests, add a separately randomized unrelated cohort, rerun without cleaning, and assert test-owned IDs or contribution deltas (and that the cohort survives cleanup).
- Cohort interference is leakage only when it changes the test-owned contribution, removes unrelated rows during scoped cleanup, or fails a cohort-independent assertion. Trace each leaked row to its creator and fix the query scoping or cleanup boundary; do not mask it with broad cleanup, blind reruns, or timeout increases.
- Find failures and make tests faster or leaner; use coverage only to locate behavior relevant to the selected improvement. Review AGENTS.md and README.md files for incongruence between tests and requirements.
- Do not raise per-test or per-file timeouts to paper over a failure (the global `teardownTimeout: 20_000` in `vitest.config.mts` is a justified exception, not a precedent). Create new entities with randomized IDs; avoid mocking internal services you can exercise directly.
- Before fixing a recurring failure signature, check `git log` and blame on the test, `vitest.config.mts`, and `test-helpers/vitest-config/**`: multiple prior patches need a fix that closes the pattern. If a prior PR's `## Follow-ups` named an action, verify the owning reference doc or `AGENTS.md` records it, and record deferred follow-ups there, not only in a PR body.
- Do not open a new worker-exit instrumentation pass; the diagnostics were removed and return only after a hosted exit is reproduced. For a post-assertion worker exit (`Worker exited unexpectedly` during teardown), check per-shard RSS/heap and `[vitest-teardown-overrun]` output first; `[vitest-teardown]` markers need `VITEST_DIAGNOSTICS=1`. Pool and isolation values are in [Pools, Isolation, and Vitest 5](../../development/reference-tests-vitest-projects.md#pools-isolation-and-vitest-5); forks-pool concurrency is bounded only by `VITEST_MAX_WORKERS` via `parseVitestMaxWorkers()`.
- Test-helper waits on a terminal event (`completed`, `failed`, drained) need their own bounded deadline that fails with a named message.
