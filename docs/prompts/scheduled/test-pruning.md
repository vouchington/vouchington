Review tests for coverage-safe deletion opportunities. Pick exactly one concrete, bounded improvement that is safe to ship in one PR — but when that improvement is a repeated fingerprint (the same tautology, duplication, or dead pattern recurring at other call sites, including in other files), fix every occurrence of that one fingerprint in this PR, not just one. Apply the canonical [Test Value and Safe Reduction](../../development/reference-tests-value-and-reduction.md) gate.

- Find tests that are unnecessary because they are hard-skipped, tautological, pure indirection, duplicated by stronger tests, or already handled by other active tests.
- Do not target credentialed/provider-backed/integration tests just because they are skipped for missing secrets, external services, local network access, or CI-only constraints.
- If you can cite at least two prior merged PRs from this prompt deleting the same low-value pattern (with PR numbers), prefer a structural fix scoped to one PR that retires the whole class — delete every remaining instance, or add an ast-grep/lint rule that fails closed on the pattern — over deleting one more instance in isolation. A shared test helper is not a valid structural fix here: [Test Value and Safe Reduction](../../development/reference-tests-value-and-reduction.md) permits helpers only for nontrivial reliability behavior (state, retry, cleanup, parsing, synchronization, error handling), not to centralize a low-value assertion. Otherwise delete the instance.
- Do not lower coverage. If deleting an active test would reduce covered lines, covered branches, patch coverage, or project coverage, rewrite or replace the test instead of deleting it. Record exact base and head evidence; historical totals use `pnpm --dir ci exec coverage-check compare-summary`, while patch coverage proves edited lines execute.
- For hard-skipped tests, document why they do not execute in normal CI before deleting them.
- For active Vitest/API tests, collect before/after coverage evidence from the owning suite and run `pnpm run coverage:patch` or `pnpm run coverage:patch:full` when applicable.
- For Playwright-only cleanup, run the relevant Playwright spec and `pnpm run no-mistakes` when selector coverage may be affected.
- Prefer deleting tests that assert only mocked call-through behavior, exact wrapper URLs already covered by route tests, or `expect(true).toBe(true)` completion checks duplicated by tests with real assertions.
- If a low-value test is the only coverage for production code, consolidate, improve the assertion, or move coverage to a higher-value test rather than deleting it.
- In the PR body, include the coverage proof used to decide the deletion was safe, when the deletion could plausibly move covered lines, covered branches, or patch coverage. When the deletion touches no instrumented production lines (a test-only tautology or duplication with no production import), state that in one line instead of omitting the section.
- For slow-test improvements, see [vitest.md](vitest.md) and [playwright.md](playwright.md) — this prompt is scoped to coverage-safe deletion, not performance.
