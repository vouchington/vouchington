## Cost Controls Already in Place

Staging targets Workers Free, which documents a fixed 10 ms CPU allowance per HTTP request, but the
account's actual enforced limit is unconfirmed — see
[#7583](https://github.com/jonathanong/filaments/issues/7583). Revisit Workers Paid only when
representative staging traffic approaches the measured CPU threshold after profiling and
optimization, an `exceededCpu` outcome occurs, or another documented Free-plan quota becomes an
actual launch constraint. Any paid-plan CPU limit must be based on measured p99 plus justified
headroom, followed by the private infrastructure receiver's staging validation.

| Control                              | Mechanism                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Aurora auto-pause                    | `db_min_acu=0` → pauses to 0 ACU after a 300s idle window; the dominant blocker to reaching that window was dozens of scheduled jobs waking staging more often than hourly, not deploy cadence — the [scheduled-job-manifest](../../../backend/modules/scheduled-job-manifest/hourly-clamp.mts) registration path floors staging schedules to hourly cadence centrally. The explicit five-minute GlideMQ telemetry exception reads Valkey and publishes CloudWatch metrics without touching PSQL, so it does not interrupt Aurora's idle window. Only deploy cadence remains a secondary limiter (see the [steady-state Aurora estimate](reference-deployment-costs-per-environment-steady-state.md#full-stack-enabled-active)); [production Aurora's `db_min_acu=1` floor never auto-pauses](reference-deployment-costs-per-environment-steady-state.md#full-stack-enabled-active). |
| GuardDuty disabled on staging        | `enable_guardduty=false` in `staging.tfvars`; saves ~$3–10/mo (production stays protected)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| AWS Budgets + Cost Anomaly Detection | Per-env monthly budget + account-wide anomaly monitor, notifying the `alerts` SNS topic immediately (`vouchington-infra/opentofu/budgets.tf`) — added after GuardDuty's post-trial billing went unnoticed. Main infra adopts an existing AWS services anomaly monitor into staging state during the fresh-apply path because that monitor type is an account singleton.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Per-task IPs over NAT gateway        | `assign_public_ip=true` on `worker-cpu` only (~$3.60/mo/task); `backend`/`web` avoid the tradeoff via IPv6-only subnets; cheaper than a NAT gateway (~$33/mo/AZ) at current scale — see [Networking](networking.md)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| CloudFront PriceClass_100            | US/CA/EU only; cheapest tier                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Fargate Spot                         | staging is Spot-only; production keeps `base=1` on-demand for web+api and uses Spot only above base count (workers stay Spot-only in every environment)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |

## Assumptions & Caveats

- All figures are **estimates derived from OpenTofu resource configuration** and
  AWS/SaaS list prices at low-to-zero traffic. They are not billed actuals.
- Usage-metered lines (CloudFront egress, Firehose GB/records, Bedrock tokens,
  Sentry events, LLM API calls) scale directly with traffic
  and PR volume.
- Aurora storage is billed even at `db_min_acu=0` (auto-paused). Storage cost
  depends on data volume.
- Ubicloud and Cloudflare plan tiers should be verified against current account dashboards for
  accurate billing.
- **Partial-month vs. run-rate:** staging launched mid-June 2026, so its first
  billing month covers only ~16 days. Figures in this doc that cite "June
  billing" are partial-month actuals; the accompanying run-rate figures are
  those actuals normalized to a full month, not a second independent
  measurement. Re-pull the per-service Cost Explorer report in August 2026,
  after safe crawl snapshot PUT dedupe has had a full month to settle, to
  confirm actuals match this doc.
- **Per-environment cost splits are not yet billing-verified.** `default_tags`
  already emits `Environment`/`Project`/`ManagedBy` on every resource (plus a
  per-resource `Component` tag on many), but Cost Explorer can't filter/group
  by them until they're activated as cost-allocation tags in the AWS Billing
  Console
  (Billing → Cost Allocation Tags) — a one-time, per-account manual step (see
  `vouchington-infra/opentofu/HUMAN_CHECKLIST.md`). Until that's done, per-env dollar figures,
  including the [production Aurora estimate](reference-deployment-costs-per-environment-steady-state.md#full-stack-enabled-active),
  are configuration-derived estimates, not confirmed account-billing splits.
