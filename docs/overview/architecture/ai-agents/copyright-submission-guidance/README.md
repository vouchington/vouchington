# Copyright Submission Guidance

`copyright-submission-guidance` gives staff advisory summaries, element checklists, and risk notes for filed counter-notices and court/CCB filings. It uses the shared AI agent lifecycle and persists immutable, encrypted output per submission and input digest. The staff panel is labeled **AI guidance — not a decision**. A human assesses every filing; guidance creates no assessment, review, deadline, restriction, hold, delivery, or workflow transition, and no workflow predicate reads it.

One agent selects the prompt, strict output schema, and parser by submission kind. Counter-notice input is an allowlist of receipt/source, statutory yes/no answers, field-presence booleans, notice context, target URLs, and restricted-target count. Names, addresses, telephone numbers, email, signature text, and claimant display name are excluded. Court/CCB filings are read from their stored `{ summary }`; personal-detail redaction (`stripPersonalDetails`) replaces email addresses, phone numbers, postal addresses, government ID numbers, dates of birth, and payment-card and IBAN numbers before prompt-injection sanitization and before hashing. The digest therefore describes the redacted text supplied to the model. Party names, other dates, docket identifiers, statute citations, and URLs remain intact. The admin MCP copyright reads apply the same redaction to free-text fields. Erased submission bodies are skipped.

Prompts and risk-note vocabularies are legal-policy content that the owner approves after AI advisor review (#1230; not a legal determination). Keep the approved prompt version and the bounded closed vocabularies together across prompt, parser, and UI; do not add a suggested action or infer that guidance changes a staff decision. The agent has no activation switch: it is advisory, limited to already-filed submissions, and its processing path remains separate from notice intake.

Dispatch is durable and replayable. Submission routes enqueue after commit; the copyright-agent reconciler recovers missing guidance for eligible in-case counter-notice and court/CCB submissions even while `COPYRIGHT_INTAKE_ENABLED` is off. Queue failure does not fail the filing. Retention erases encrypted guidance with its submission, and read models treat erased output as absent.

When guidance existed before a decision, statement-of-reasons notices disclose AI assistance through the shared builder. Fixed-text counter-notice decision email, in-app decision update, and acceptance forwarding use the same sentence: “Automated tools assisted with processing this case.” A filing receipt is not a decision and gets no disclosure. Any future hold-decision notice must use the shared statement-of-reasons builder.
