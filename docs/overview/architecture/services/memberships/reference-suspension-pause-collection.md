# Suspension pause collection

[Back to Memberships](README.md#suspension-pause-collection)

Account suspension writes one `membership_pause_collection_work_items` row. After commit, the
membership worker sets Stripe `pause_collection.behavior` to `void` on the direct subscription, or
clears it when the suspension is lifted. The membership projection stays `active`.

## Durable transitions

| Failure mode                                       | Detectable state                                                                       | Recovery/reconciliation path                                                                                                 | Idempotency guarantee                                                      | Evidence                                                                                        |
| -------------------------------------------------- | -------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| Dispatch failure                                   | Work row remains unleased after the post-commit enqueue is lost                        | The minute dispatcher claims unleased rows with `FOR UPDATE SKIP LOCKED`                                                     | The row is the job; no Stripe call happens until a lease is confirmed      | `pause-collection/sync.test.mts` (`reclaims an expired pause-collection lease`)                 |
| Provider non-consumption                           | Stripe update throws and the lease columns are cleared                                 | The same generation is claimed again                                                                                         | Logical key includes user, `requested_at`, subscription, and void or clear | `pause-collection/sync.test.mts` (`retries a Stripe update that was not accepted`)              |
| Provider consumption followed by DB-commit failure | Stripe already has `void` while the work row remains                                   | The retry retrieves that state, skips the update, and deletes the row                                                        | Retrieve-then-skip plus the same Idempotency-Key                           | `pause-collection/sync.test.mts` (`skips another update when Stripe already voided collection`) |
| Durable commit followed by reply loss              | The work row is gone and a second delivery has no lease to claim                       | The second delivery returns without Stripe                                                                                   | Completion deletes only the matching generation and lease                  | `pause-collection/sync.test.mts` (`ignores a repeated delivery`)                                |
| Retry/reconciliation                               | `lease_expires_at` is due, or the row was never leased                                 | Dispatcher replaces an expired lease; the old token cannot complete or release                                               | A new lease token fences the same `requested_at`                           | `pause-collection/sync.test.mts` (`reclaims an expired pause-collection lease`)                 |
| TTL expiry                                         | Lease columns are set and `lease_expires_at` is at most five minutes after `leased_at` | The expired-lease index serves the next dispatcher claim                                                                     | Only the current lease token can update or delete the generation           | `pause-collection/sync.test.mts` (`reclaims an expired pause-collection lease`)                 |
| Orphan cleanup                                     | The user row is gone, or Stripe has no manageable direct subscription                  | `user_id` cascades on user delete; a missing, canceled, or `incomplete_expired` subscription deletes the work row as a no-op | No Stripe update is sent for a missing or terminal subscription            | `pause-collection/sync.test.mts` (`treats a missing Stripe subscription as a no-op`)            |
| Normal terminal removal                            | Stripe `pause_collection` matches the open suspension                                  | The worker deletes the matching generation and lease                                                                         | A repeated delivery finds no row                                           | `pause-collection/sync.test.mts` (`sets pause collection to void`)                              |

## Stripe identity

| Column                        | Pause collection                                                                                                                                                      |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Intent owner                  | The suspension or lift transaction writes `requested_at` before enqueue. The worker does not mint a new generation.                                                   |
| Provider verb                 | POST `subscriptions.update`. Stripe accepts `Idempotency-Key` on that verb.                                                                                           |
| Logical idempotency key       | `membership-pause-collection:<userId>:<requestedAt>:<subscriptionId>:void` or `:clear`. It does not include the lease token.                                          |
| Provider idempotency key      | The same string, forwarded as `Idempotency-Key`.                                                                                                                      |
| Receipt/retention horizon     | The work row is the receipt until completion deletes it. After that, the Stripe subscription's `pause_collection` is the provider state.                              |
| Replacement/supersession      | A later suspension change writes a new `requested_at` and clears the lease. The previous lease's delete matches zero rows.                                            |
| Rolling-version compatibility | One current contract. The payload is `userId`, `requestedAt`, and an optional `leaseToken`. The worker reads the open suspension from PostgreSQL.                     |
| Concurrent-winner resolution  | The lease token is the winner for one generation. Leases of that same generation share one Stripe key. A superseded caller returns without releasing the newer lease. |
