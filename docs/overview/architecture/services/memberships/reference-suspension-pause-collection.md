# Suspension pause collection

[Back to Memberships](README.md#suspension-pause-collection)

Account suspension writes one `membership_pause_collection_work_items` row. After commit, the
membership worker sets Stripe `pause_collection.behavior` to `void` on the direct subscription, or
clears it when the suspension is lifted. The membership projection stays `active`.

## Stripe identity

| Column                        | Pause collection                                                                                                                                                                                                   |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Intent owner                  | The suspension or lift transaction writes `requested_at` before enqueue. The worker does not mint a new generation.                                                                                                |
| Provider verb                 | POST `subscriptions.update`. Stripe accepts `Idempotency-Key` on that verb.                                                                                                                                        |
| Logical idempotency key       | `membership-pause-collection:<userId>:<requestedAt>:<subscriptionId>:void` or `:clear`. It does not include the lease token.                                                                                       |
| Provider idempotency key      | The same string, forwarded as `Idempotency-Key`.                                                                                                                                                                   |
| Receipt/retention horizon     | The work row is the receipt until completion deletes it. After that, the Stripe subscription's `pause_collection` is the provider state.                                                                           |
| Replacement/supersession      | A later suspension or lift writes a new `requested_at`, clears the lease, and resets `attempt_count`, `available_at`, `last_failed_at`, and `last_failure_message`. The previous lease's delete matches zero rows. |
| Rolling-version compatibility | One current contract. The payload is `userId`, `requestedAt`, and an optional `leaseToken`. The worker reads the open suspension from PostgreSQL.                                                                  |
| Concurrent-winner resolution  | The lease token is the winner for one generation. Leases of that same generation share one Stripe key. A superseded caller returns without releasing the newer lease.                                              |
