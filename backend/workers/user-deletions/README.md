# User Deletions Worker

The IO worker processes one fenced, bounded account-deletion batch per delivery. A committed batch
returns the next persisted attempt for enqueue; if enqueue fails, the queue's recovery dispatcher
finds the durable unfinished request and resumes it.

On a terminal GlideMQ attempt failure, the worker passes that boundary to the lifecycle service,
which rotates the persisted token before the failed job is retained. Ordinary recovery retains an
unstarted token so an existing queued job remains the canonical delivery.

Concurrency is fixed at two so independent deletions can progress without multiplying database lock
pressure. Provider cleanup is retried from durable work rows and must complete before the internal
deletion request is finalized.
